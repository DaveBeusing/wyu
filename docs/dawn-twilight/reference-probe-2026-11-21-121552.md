## Rendering approach requiring a design decision

### Bounded direct-model follow-up

The follow-up removes repeated shader divisions by uploading reciprocal normalized
scale heights and combining the radius division in solar visibility. Validation
already bounds normalized heights to [0.0001, 1], so reciprocals are finite in
[1, 10000]. The stable sphere solver, eight view samples, four solar samples,
physical parameters, 40-DWORD layout and resource behavior remain unchanged.

With the same compiler, static DXIL `fdiv` count falls from 25 to 12; `sqrt` and
`exp` counts remain unchanged. This is an instruction comparison, not measured
GPU speedup. Release compilation and all 15 shader validations pass. Four targeted
WARP/NVIDIA tests pass, with zero skips, including twilight and orbital/rebase
coverage. Every pixel of five WARP and five NVIDIA composition fixtures also
matches the corresponding **pre-change** captured image exactly; alpha and image
extents are unchanged. These fixed fixtures do not prove equality for all possible
inputs or full installed-game visual acceptance.

Evidence: Groundwork `artifacts/sky-algebra-tests/graphics.trx`,
`artifacts/sky-algebra-image-comparison.json` and
`artifacts/sky-algebra-99ed593b2f354a20a070c903bf93b2b1/`.
Independent code and security reviews find no source defects. The small change
has no renewed reference-machine timing evidence and is not claimed to close
the remaining +5/+8% frame-cost blocker.

### Proposed larger change

A bounded GPU lookup prototype could share atmosphere integration between pixels.
It must preserve the physical parameters, sun/stars, approved dawn/dusk curve and
clock behavior, plus **all original performance/resource limits**:

- Fixed-size, resolution-independent tables; peak incremental memory at most
  **4 MiB**, including live/retiring/staging overlap; one sky draw, no additional
  resolution-dependent targets or terrain/mesh uploads.
- Charge all generation, updates, dispatches, barriers, lookup work and handoff
  overlap inside the original timing/memory intervals. No acceptance-only cache
  warming or stale tables on time/profile/altitude changes.
- Retain direct integration as a comparison oracle. Compare day, dawn, dusk,
  night, horizon, orbital limb, rebase, Save/Continue and transitions. Report
  interpolation error explicitly. No new image-error allowance is approved here.
- Require independent code/security/visual reviews, mandatory CI, and the complete
  unchanged reference protocol. Failure retains CHANGES REQUIRED.

A solar-depth table alone may be insufficient; radiance lookup may also be needed.
Interpolation changes the numerical rendering approach. Table dimensions and image
equivalence must be demonstrated by a prototype before approval; no performance
or visual-equivalence result is claimed. This proposal is not implemented.
