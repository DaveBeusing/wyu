The follow-up implementation therefore separates an immutable, complete lookup

removes unnecessary root-distance computation only where the exact geometry
class is sufficient; it is eligible only if strict before/after captures and
fallback masks remain byte-identical. Neither change is accepted as a reference
performance fix until measured on the designated hardware.

## Scheduling evidence and remaining approval gates

The optional `-GpuSchedulingTrace` diagnostic captures a unique owned Windows
DxgKrnl data collector per replay, including startup and handoffs. Its circular
ETL is capped at 256 MiB, buffers are bounded, and server-side runtime is at most
720 seconds. Only that owned collector is stopped/deleted; no global WPR stop,
clock/power/display change or automatic elevation is performed. The selected
observational keyword mask excludes ForceVsync and StablePower. See Microsoft's
[logman reference](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/logman-create-trace)
and [GPUView trace requirements](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/generating-a-trace-for-gpuview).

Capture requires an elevated PowerShell; missing privilege/tool/provider is
explicitly `UNAVAILABLE`. Files alone mean `CAPTURED`, not verified event loss or
complete coverage: circular data can wrap. A hard-killed parent leaves a timed,
eventually stopped collector configuration; normal cleanup removes it. ETLs may
contain system-wide GPU process information. Their overhead makes the traced
run diagnostic only; a subsequent original untraced qualification is required.
